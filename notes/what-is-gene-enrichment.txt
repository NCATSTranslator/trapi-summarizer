⏺ OK, here's the lay explanation:

  ---
  What's going on here, in plain language

  The problem this solves

  TRAPI is the API used by the NCATS Biomedical Data Translator — a big federated system that answers
  biomedical questions like "What drugs might treat Alzheimer's disease?" The answer comes back as a
  knowledge graph: a huge structured blob of nodes (genes, drugs, diseases, biological processes)
  connected by edges (relationships like "gene X regulates process Y" or "drug Z targets gene W").
  These responses can contain hundreds of genes and thousands of edges. No human is going to read that
  JSON and understand it.

  What PiGEaN / NMF does

  When the knowledge graph comes back with a big pile of genes implicated in a disease, a natural
  question is: "OK, but what are these genes actually doing? Are there patterns?"

  That's what the Broad Institute's PiGEaN (Polygenic Informed Gene Networks) API does. You hand it a
  list of gene names, and it runs NMF — Non-negative Matrix Factorization on them. NMF is a
  dimensionality-reduction technique (think: cousin of PCA). In this context it means:

  ▎ Take this big flat list of genes and find latent factors — hidden groupings where genes cluster
  together because they participate in similar biological processes.

  The output (visible in gene-bigger.json) is structured as numbered factors, each with two views:
  
  1. Gene set groupings — Each factor maps to known biological pathways/processes (from databases like
  Gene Ontology, KEGG, WikiPathways). For example, Factor 3 in the Alzheimer's example maps to
  autophagy-related processes (MACROAUTOPHAGY, REGULATION_OF_CATABOLIC_PROCESS), and Factor 9 maps to
  neuron cell death (NEURON_APOPTOTIC_PROCESS).
  2. Gene groupings — The same factors, but showing which specific genes cluster under each. Factor 3
  has MTOR, SIRT1, ULK1 — all well-known autophagy regulators. Factor 9 has CASP3, CASP9, TNF — classic
   apoptosis genes.

  So NMF turns "here are 200 genes" into "here are 10 themes, and here's which genes and which
  biological processes belong to each theme."

  What this repo does with it

  The pipeline is:

  1. Query TRAPI → get a knowledge graph with hundreds of gene nodes relevant to a disease
  2. Extract the gene list from the KG
  3. Send genes to PiGEaN → get back the factor groupings
  4. Format the factors as structured text and hand it to OpenAI with instructions (in
  instructions-what-biological-nmf.txt) that say, essentially: "You're a biomedical expert. Here are
  NMF-derived factor groupings for genes related to a disease. Identify patterns, assess plausibility,
  and write a concise literature-review-style summary."

  The end result: a researcher asks "what biological processes impact Alzheimer's?" and instead of
  getting a 50MB JSON graph, they get a few paragraphs explaining that the implicated genes cluster
  around autophagy dysfunction, neuronal apoptosis, MAPK signaling, neurogenesis impairment, etc. —
  with the LLM assessing which themes look well-supported and which are more speculative.

  In short: NMF finds the signal in a noisy gene list, and the LLM translates that signal into prose a
  human can act on.

⏺ Sure. "Factor" in the NMF context is a piece of jargon that's doing a lot of work, so let me unpack
  it.

  The intuition

  Imagine you have 200 genes implicated in Alzheimer's. You don't know why they showed up — they were
  just in the knowledge graph. But many of them are probably there for related reasons. Some are
  involved in cell death, some in inflammation, some in protein cleanup, etc. These underlying reasons
  are the factors.

  A factor is a hidden (latent) pattern that the algorithm discovers. You don't name them in advance —
  the math finds them, and then you look at what clustered together and interpret what it means.

  What NMF is actually doing

  NMF takes a big matrix — in this case, something like "genes vs. known biological pathways, scored by
   association strength" — and decomposes it into two smaller matrices whose product approximates the
  original. The columns of one of those matrices are the factors.

  Each factor is essentially a weighted blend: "these genes load heavily on this factor, and these
  biological pathways load heavily on this factor." Because NMF forces all values to be non-negative
  (no subtractive cancellation), each factor tends to correspond to a coherent, additive biological
  theme — which is why it's preferred here over something like PCA, which can produce factors that are
  harder to interpret.

  Concrete example from the Alzheimer's data

  Factor 3 grouped:
  - Gene sets: MACROAUTOPHAGY, REGULATION_OF_CATABOLIC_PROCESS, etc.
  - Genes: MTOR, SIRT1, ULK1, WIPI1, PRKAA2

  The algorithm didn't know what autophagy is. It just noticed that these genes and these pathways had
  correlated association patterns, so it grouped them into one factor. A human (or LLM) then looks at
  it and says "that's the autophagy factor."

  Factor 9 grouped:
  - Gene sets: NEURON_APOPTOTIC_PROCESS, REGULATION_OF_NEURON_APOPTOTIC_PROCESS
  - Genes: CASP3, CASP9, TNF, CDK5

  Same idea — the algorithm found a cluster, and it clearly corresponds to neuronal cell death.

  So "factor" just means...

  A discovered cluster of things that co-vary. It's the algorithm's way of saying "I don't know what to
   call this, but these genes and these pathways seem to be part of the same underlying story." The
  number of factors (10 in the Alzheimer's example) is a parameter you choose — it controls how many
  themes you want the decomposition to find.

⏺ OK, let me start over more carefully.

  The input

  You have a flat list of gene names. Say 200 genes pulled from a knowledge graph. That's it.

  What the API knows that you don't

  Independently of your query, large public databases (Gene Ontology, KEGG, WikiPathways, etc.) have
  already catalogued thousands of named biological pathways — things like NEURON_APOPTOTIC_PROCESS or
  REGULATION_OF_CATABOLIC_PROCESS. These names come from those databases, not from the NMF algorithm.
  They're pre-existing, curated human knowledge: biologists studied these processes, named them, and
  recorded which genes participate in each one.

  So there exists, conceptually, a big lookup table that the API has access to:

                      Autophagy    Neuron Death    Inflammation    ...
  MTOR                  strong        weak            none
  CASP3                 weak          strong          medium
  TNF                   none          medium          strong
  SIRT1                 strong        none            weak
  ...

  Each cell says "how strongly is this gene associated with this pathway?" That table is the matrix.

  What NMF does to that matrix

  The algorithm's job is to look at that big table and find groups of rows and columns that move
  together. Genes that have similar patterns across pathways get grouped. Pathways that have similar
  patterns across genes get grouped. Each such group is a factor.

  The "two smaller matrices" thing just means: instead of storing the full table, NMF compresses it
  into (a) a "which genes belong to which factors" table and (b) a "which pathways belong to which
  factors" table. That's the decomposition. You can ignore the linear algebra — the point is just
  clustering.

  What "Factor 3" means

  The factors are numbered arbitrarily — Factor 0, Factor 1, ... Factor 9. The number 3 has no meaning.
   It's just the third cluster the algorithm found. You asked for 10 factors (a parameter in the API
  call: the code doesn't set it explicitly, but PiGEaN has a default), so you get 10 groups back.

  Each factor gives you two lists:

  - Top genes in this cluster: e.g. MTOR, SIRT1, ULK1
  - Top pathways in this cluster: e.g. MACROAUTOPHAGY, REGULATION_OF_CATABOLIC_PROCESS

  That's saying: "these genes and these pathways form a coherent group — they co-occur in the data." A
  human then looks at the pathway names and says "ah, factor 3 is about autophagy."

  So the full picture

  1. You start with 200 unlabeled genes from a KG
  2. The API already knows which pathways each gene is involved in (from public databases)
  3. NMF clusters everything into N groups (factors) where genes and pathways that go together end up
  in the same group
  4. You get back: "here are 10 themes in your gene list, and here are the pathway names and gene names
   for each theme"

  The pathway names (NEURON_APOPTOTIC_PROCESS, etc.) are just labels that already existed in the
  databases. NMF didn't invent them — it just figured out which of your 200 genes cluster around which
  of those known pathways.

⏺ This is exactly the right question, and the data makes the problem concrete. Here's the situation:

  The scale mismatch

  Looking at your actual data (e.g. data/small.json — Alzheimer's / Clioquinol):

  - Full KG: ~21 genes, ~36 nodes total
  - Single result subgraph (one drug's reasoning chain): typically 0-3 genes, often zero

  That's because a single result's reasoning path is usually something like Drug → treats → Disease,
  with maybe one gene as an intermediary. The genes in the KG are mostly supporting context shared
  across all results, not bound to any single drug's reasoning chain.

  Why this matters for NMF

  NMF is a statistical decomposition. It needs enough data points to find patterns. Here's a rough way
  to think about "too few":

  - 1-3 genes: Meaningless. NMF will either fail or return factors that are just restating what the
  input genes already are. You're asking "find hidden clusters" in a list you can read with your eyes.
  There's nothing latent to discover.
  - 4-10 genes: Fragile. You might get factors, but each factor will have 1-2 genes in it. You're
  carving a small list into smaller lists — a human could do this by inspection. The pathway
  associations will be dominated by whichever gene is most studied (publication bias). Not trustworthy
  enough for an expert audience.
  - ~15-30 genes: The plausible minimum range. Enough for the clustering to actually reveal non-obvious
   groupings. You start seeing factors that contain genes you wouldn't have manually grouped together,
  which is where the value is.
  - 50+ genes: Comfortable. This is the regime where NMF genuinely tells you something you couldn't see
   by inspection.

  The practical problem

  Your current architecture processes one result at a time. One result's subgraph rarely has enough
  genes for NMF to be useful. You have a few options to reason about:

  1. Use the full KG's gene set even when summarizing a single result. The NMF themes would be
  disease-wide, not drug-specific. The LLM could then be instructed to relate the relevant themes back
  to the specific drug. Downside: the gene clustering has nothing to do with the drug being summarized
  — it's just "genes associated with Alzheimer's broadly."
  2. Aggregate genes across N results — pick the top 10-20 results, collect all unique genes from their
   subgraphs, run NMF on that pool. More genes, but now the NMF output is an amalgam rather than
  specific to any one result.
  3. Don't run NMF for single-result summaries at all. Use it only when the user is asking for a
  multi-result or whole-KG summary (which nmf_driver.py already does — it currently pulls genes from
  the entire KG). For single-result summaries, the existing trapi_summarizer path is fine: the value
  there is the LLM synthesizing the edges and publications, not gene clustering.
  4. Run NMF on the full KG gene set, then filter the output. Get all 10 factors, but when summarizing
  a single result, only present the factors whose top genes overlap with that result's subgraph. This
  way you get statistically robust factors but surface only the relevant ones.

  My take on how to reason about it

  The question isn't really "what's the minimum?" — it's "does this tool answer a question that exists
  at this granularity?" For a single drug's reasoning chain, the interesting question is "why does this
   drug treat this disease?" — and the answer is in the edges and publications, which is what your
  existing summarizer already handles well. NMF answers a different question: "what are the major
  biological themes across this gene set?" That question only makes sense when the gene set is large
  enough to have themes.

  So the most natural boundary is probably: NMF is a whole-KG or multi-result tool, not a per-result
  tool. Trying to force it into the per-result pipeline will either produce unreliable output or
  require pulling in genes that aren't specific to that result anyway.
